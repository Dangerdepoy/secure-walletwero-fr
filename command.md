WIFI CONNECT — MASTER UI/UX VISUAL REFINEMENT PROMPT

CONTEXTE

Le projet actuel contient déjà un UI/UX Playground fonctionnel destiné à tester et visualiser :

* les différentes pages
* les composants
* les boutons
* les interactions
* les animations
* les modals
* les menus
* les cartes
* les tableaux
* les états des composants
* la navigation
* le responsive
* le système visuel global de WiFi Connect

NE PAS repartir de zéro.

Le Playground existant constitue la base de travail.

La mission est maintenant de faire évoluer et perfectionner cette base visuellement, afin d’obtenir une interface qui ressemble à un produit SaaS réellement conçu et finalisé par une équipe UI/UX expérimentée.

2. OBJECTIF PRINCIPAL

Transformer le Playground actuel en une véritable vitrine du design de WiFi Connect.

L’utilisateur doit avoir immédiatement l’impression d’utiliser :

un SaaS moderne, premium, rapide, précis et extrêmement bien fini.

Le design doit être :

minimaliste
+
élégant
+
technologique
+
fonctionnel
+
désirable
+
cohérent

Le résultat doit évoquer la qualité visuelle des meilleurs SaaS modernes comme :

* Vercel
* Cloudflare
* Linear
* Stripe
* GitHub
* Raycast

mais sans copier leur identité visuelle.

WiFi Connect doit avoir sa propre identité.

⸻

3. PRIORITÉ ABSOLUE : LE RENDU VISUEL

Ne pas chercher simplement à faire fonctionner les composants.

Ils fonctionnent déjà.

La priorité de cette itération est :

VISUAL QUALITY

Le résultat doit être jugé sur :

* l’équilibre
* la précision
* la cohérence
* la beauté
* la lisibilité
* la hiérarchie
* les proportions
* les détails
* les interactions
* le sentiment de finition

⸻

4. NE PAS SURDESIGNER

Le résultat ne doit jamais devenir chargé.

Éviter :

* gradients excessifs
* glow inutile
* ombres fortes
* énormes boutons
* couleurs multiples
* cartes surchargées
* animations excessives
* décorations inutiles

La sophistication doit venir de :

la précision.

Pas de la quantité d’effets.

⸻

5. PRINCIPLE : EVERYTHING HAS ITS PLACE

Chaque élément doit sembler avoir été placé volontairement.

Il ne doit jamais y avoir :

* d’espace bizarre
* d’alignement approximatif
* de bouton mal proportionné
* de texte trop proche
* d’icône mal centrée
* de carte trop grande
* de carte trop petite
* de section déséquilibrée
* de composant qui semble ajouté après coup

Chaque élément doit appartenir naturellement à la composition.

⸻

6. PIXEL-PERFECT REFINEMENT

Effectuer une véritable passe de finition sur tout le Playground.

Examiner particulièrement :

Typography

* tailles
* poids
* line-height
* letter-spacing
* contraste
* hiérarchie

Layout

* largeur
* hauteur
* alignement
* grille

Components

* dimensions

* border
* shadow
* icône
* positionnement

Interaction

* hover
* focus
* active
* pressed
* loading
* disabled
* success
* error

Rien ne doit sembler approximatif.

⸻

7. VISUAL HIERARCHY

Chaque écran doit avoir une hiérarchie évidente.

L’utilisateur doit comprendre immédiatement :

1. où il se trouve
2. ce qui est important
3. ce qu’il peut faire
4. quelle action est prioritaire
5. quelles informations sont secondaires

Ne pas donner le même poids visuel à tous les éléments.

⸻

8. ESPACE ET RESPIRATION

Utiliser généreusement l’espace vide.

Ne pas remplir l’écran simplement parce qu’il reste de la place.

Mais éviter également les espaces artificiellement énormes.

Chercher un équilibre entre :

information density

et

visual breathing room.

L’interface doit être dense lorsqu’elle traite des données complexes, mais toujours respirable.

⸻

9. INTERACTIONS — MAKE IT FEEL ALIVE

Toutes les interactions importantes du Playground doivent sembler naturelles.

Améliorer si nécessaire :

* hover
* click
* dropdown
* sidebar
* modal
* drawer
* tooltip
* tabs
* toggle
* checkbox
* switch
* toast
* command palette
* navigation
* transitions

Les animations doivent être :

* rapides
* fluides
* discrètes
* intentionnelles

Elles doivent donner une sensation de qualité, pas attirer inutilement l’attention.

⸻

10. MICRO-INTERACTIONS

Ajouter ou améliorer les micro-interactions lorsque cela apporte réellement quelque chose.

Exemples :

Button
→ hover
→ press
→ loading
→ success
Copy
→ Copied ✓
Router
→ Connecting
→ Online
Delete
→ Confirmation
→ Deleting
→ Deleted
Modal
→ smooth entrance
→ interaction
→ smooth exit

Chaque action doit avoir un feedback clair.

⸻

11. COMPONENT CONSISTENCY

Tous les composants doivent sembler appartenir au même produit.

Un bouton utilisé sur Dashboard doit avoir la même logique visuelle que celui utilisé sur Settings.

Même principe pour :

* cards
* inputs
* tables
* badges
* dropdowns
* tabs
* modals
* notifications
* navigation

Créer ou améliorer les composants réutilisables plutôt que créer des variantes arbitraires.

⸻

12. DESIGN TOKENS

Centraliser autant que possible :

* couleurs
* typographie
* spacing
* radius
* shadows
* transitions
* dimensions

Éviter les valeurs visuelles arbitraires dispersées dans le code.

Le Playground doit commencer à ressembler à un véritable Design System.

⸻

13. RESPONSIVE

Ne pas oublier que le design doit rester élégant sur :

* desktop
* laptop
* tablet
* mobile

La version mobile ne doit pas être une simple réduction du desktop.

Repenser les compositions lorsque nécessaire.

⸻

14. UTILISER LES IMAGES COMME RÉFÉRENCES DE DIRECTION

Pour chaque nouvelle image fournie, demander :

“Qu’est-ce qui rend cette interface aussi bonne ?”

et non :

“Comment puis-je copier cette interface ?”

Identifier les principes.

Par exemple :

Image
↓
Composition
↓
Grid
↓
Spacing
↓
Typography
↓
Color
↓
Component treatment
↓
Interaction
↓
Adaptation WiFi Connect

Les références doivent servir à améliorer le niveau de finition de WiFi Connect.

⸻

15. NE PAS CASSER LE PLAYGROUND

Avant chaque modification importante :

* comprendre le composant existant
* comprendre ses dépendances
* conserver son comportement
* modifier uniquement ce qui est nécessaire

Ne pas supprimer des fonctionnalités simplement pour simplifier le code.

Si une amélioration visuelle nécessite une refactorisation, la faire proprement.

17. FINAL DESIGN REVIEW

Avant de considérer cette itération terminée, effectuer une dernière revue comme si tu étais un Senior Product Designer évaluant le produit.

Demande-toi :

Est-ce que tout est aligné ?

Est-ce que quelque chose semble inutile ?

Est-ce qu’une section paraît trop chargée ?

Est-ce qu’un bouton attire trop l’attention ?

Est-ce que les espacements sont cohérents ?

Est-ce que les icônes sont parfaitement intégrées ?

Est-ce que la typographie semble premium ?

Est-ce que les interactions donnent envie d’utiliser le produit ?

Est-ce que l’ensemble semble provenir d’un seul Design System ?

Est-ce que quelque chose semble encore “prototype” ?

Si quelque chose semble encore être un prototype, le polir avant de considérer le travail terminé.

craftsmanship
